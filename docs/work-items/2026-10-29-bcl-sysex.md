# BCL/SysEx implementation tickets

Created during implementation on 2026-10-29; not backdated as pre-existing tracker issues. These are repository-local work items, not newly published GitHub issues. Source/reader/model/time/vendor provenance and the compatibility/safety contract are in [the implementation dossier](../BCL-SYSEX-EDITOR.md).

## Objective and invariants

Reuse the existing BCL parser, command20 envelope, storage/history and host. Add working local custom programming without reinterpreting an unknown program as OFF. No physical experiment, new grant or publication is part of this implementation authorization. Old standard assignments and sequencer behavior must retain their regression evidence.

## Acceptance for the delivered local slice

- [x] Model64 and historical framing fixtures roundtrip; malformed ASCII/data/sequence/model inputs fail closed.
- [x] Standard CC/NRPN projections retain existing behavior; custom source/comments remain exported and never turn into an OFF hardware write.
- [x] Values0/63/64/127 and selected14-bit slices simulate; out-of-range and opaque programs cannot emit guessed bytes.
- [x] JSON draft/library retains custom definitions; Apply is single-target and stops emission; standard restore/global Undo/reload are exercised in a fake-port browser.
- [x] Local editing, preview and export emit no custom, standard assignment, OFF, STORE or firmware write.
- [ ] Final full suite/typecheck/build, browser/sequencer/offline regressions and measured codec/bundle evidence recorded below.
- [ ] Physical custom execution/feedback/persistence: pending, no hardware operation authorized by this checklist.

This is a functional **local-programming slice**, not completion of the full two-part proposal. In particular L8 is not marked complete merely because the vendor app has a BCL writer.
